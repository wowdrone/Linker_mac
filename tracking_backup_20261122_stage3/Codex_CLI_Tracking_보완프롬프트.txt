1. [P0] 안전·정책 불일치 정리 — 사용자 결정 필요 항목
- 원래 지침은 "브라우저에 새 비행제어 엔드포인트를 추가하지 말라"였다. 그런데 tracking_dashboard.py는 mode_prepare / mode_commit / mode_cancel로 브라우저에서 비행 모드 변경 요청을 받는다. docs/tracking_monitor.md는 여전히 "새 브라우저 엔드포인트는 없다"고 적혀 있다.
- 이 항목은 코드를 임의로 지우거나 유지 확정하지 말고, 아래 두 안을 모두 구현 가능하게 설계하되 기본값은 A로 하라.
  A) 기본값: 브라우저 모드 변경 비활성. QSettings 키 tracking/web_mode_change(기본 false)가 true일 때만 mode_* 명령을 큐에 받는다. false이면 validate 단계에서 거부하고 페이지는 모드 버튼 대신 "앱 창에서만 모드 변경 가능" 안내를 표시한다. 설정을 바꾸는 UI는 PyQt Tracking 창에만 두고 브라우저에서는 바꿀 수 없게 하라.
  B) 활성 시: 기존 티켓·TTL·재검증·1회 송신·HEARTBEAT 확인 흐름을 유지하고, 추가로 commit 직전 선택 기체의 HEARTBEAT 신선도·모드·armed가 티켓과 같은지 다시 확인하라(이미 있으면 테스트로 증명하라).
- 로컬 프로세스는 GET / 로 토큰이 박힌 페이지를 받을 수 있다(기존 drive_dashboard와 같은 구조). 모드 변경이 켜진 경우에 한해 이 위험을 문서에 명시하고, 대시보드 시작 시 PyQt 창에 "브라우저 모드 변경 허용됨" 경고를 표시하라.
- 결정 결과와 남은 위험을 docs/tracking_monitor.md에 사실대로 갱신하라.

5. [P1] 일관성·정리
- 합성 모의 영상에서 상단 표시는 SIMULATION인데 service.banner()는 "MONITOR ONLY"를 쓴다. demo 또는 sink.enabled이면 배너도 SIMULATION으로 표시하라(app.monitor와 같은 규칙 하나로 통일).
- PyQt 창을 닫을 때 브라우저 대시보드가 열려 있으면 세션을 유지하고 있다. 이 동작을 창 닫기 시 확인 문구로 알리고, 대시보드도 함께 닫는 선택지를 제공하라.
- 대시보드 기본 포트 8766이 사용 중이면 임의 포트로 바뀐다. 실제 URL을 PyQt 창과 이벤트 로그에 표시하라(이미 로그는 있음).
- 폴더 정리: 루트의 .lk_stage.tgz(검증용 임시 압축파일)는 삭제 대상으로 보고만 하라(직접 삭제는 사용자 확인 후). .gitignore에 tracking_backup*/, tracking_validation/, *.tgz, .DS_Store 추가를 제안하고, spec이 백업 폴더를 번들에 넣지 않는지 확인하라.

6. [P2] 성능·실영상 준비
- _publish_web()은 Qt 스레드에서 cv2.imencode를 최대 10Hz로 수행하고, PyQt 창은 새 프레임마다 cvtColor로 전체 해상도 변환을 한다. 1080p·4K 소스에서 UI 스레드 시간을 측정(프레임당 ms)해 보고하라. 33ms 예산을 넘으면 JPEG 인코딩을 별도 워커(최신 1개 슬롯)로 옮기고, 표시용 변환은 표시 크기로 축소한 뒤 수행하라. 추적 입력 해상도는 바꾸지 말라.
- 현재 확인된 실제 입력은 카메라 장치 0(노트북/USB)이다. HM30 RTSP 실영상, 지연(프레임 나이) 분포, timeout 0.3초 적정성은 아직 검증되지 않았다. 녹화 파일 재생 기반 측정 도구(tools/에 스크립트)를 추가해 프레임 나이·처리 FPS·LOST 사유 분포를 CSV로 남기게 하라. 실제 HM30 연결은 자동으로 하지 말라.
