7-1. 로컬 중계 구성(Linker_mac/tools/video_relay/)
- mediamtx를 우선 후보로 하되 자동 설치하지 말라. 설치 여부와 버전을 확인하고, 없으면 설치 명령(예: brew)만 보고하라. 설치된 버전의 공식 설정 키 이름을 확인한 뒤 설정 파일을 작성하라(기억에 의존한 키 이름 금지).
- 설정 요구사항: 중계 서버는 127.0.0.1에만 바인드. 카메라→중계 구간은 TCP로 수신(H.265를 UDP로 받으면 RTP 패킷 크기 오류 사례가 있음). 사용하지 않는 프로토콜(RTMP/HLS/WebRTC/SRT 등)은 끈다. 카메라 주소는 설정 파일에 직접 박지 말고 실행 인자나 별도 로컬 설정에서 받으며, 비밀번호가 있으면 로그·화면·문서에서 가린다(mask_url 규칙). 중계 경로 이름은 하나로 고정(예: rtsp://127.0.0.1:8554/cam).
- 시작/정지 스크립트(video_relay_start.command, video_relay_stop.command)와 상태 확인 방법을 제공하라. Linker가 중계 서버를 자동 실행하지는 말라(시작 시 자동 연결 금지 원칙 유지).
- 중계 서버가 카메라 연결을 잃었다가 복구될 때 Linker 쪽에서 session_id가 바뀌고 이전 추적이 폐기되는지(기존 재연결 규칙) 녹화 파일 기반 중계로 시험하라.

- 영상 소스 프리셋에 "로컬 중계(권장)" 항목을 추가하라. 실제 HM30 주소라고 단정하지 말고, 중계 서버가 꺼져 있으면 연결 실패 사유를 명확히 표시하라.
- _SharedCapture pool key 정규화: 스킴·호스트 대소문자, 기본 포트 생략/명시, 끝의 '/' 차이 때문에 같은 카메라에 디코더가 2개 생기지 않게 하라. 자격증명 포함 여부가 다른 같은 주소의 처리 규칙을 명시하고 테스트하라.
- 동일 호스트(같은 카메라 IP)로 RTSP 연결이 2개 이상 열리면 PyQt 창과 이벤트 로그에 "같은 카메라에 직접 연결 n개 · 무선 링크 부하 증가 · 로컬 중계 사용 권장" 경고를 표시하라. Linker가 아는 범위(자기 pool)만 판단하고 Sentinel 연결 수를 추정해서 단정하지 말라.
- 디코딩 지연 누적 감지: 디코더의 실제 수신 FPS가 소스 FPS보다 지속적으로 낮거나(예: 5초 이상 80% 미만) read() 간격이 비정상적으로 몰려 들어오면(버스트) "디코딩 밀림·지연 누적 가능" 경고를 표시하라. 임계값은 설정 가능하게 하고 합성 시험으로 검증하라.
- Tracking 창·브라우저 대시보드의 영상 상태에 "직접 연결 / 로컬 중계" 경로를 표시하라.

7-3. 브라우저 영상 표시 원칙
- 브라우저 영상(Tracking·Sentinel Legacy 대시보드)은 JPEG 스냅샷(최대 약 10장/초)이며 앱 창보다 늦다. 브라우저 영상 위에 "관찰용 · 조종 판단에 사용 금지" 표시와 브라우저 기준 영상 나이(앱 수신 시각 → 브라우저 표시까지)를 항상 표시하라.
- 여러 탭·여러 대시보드가 열려도 JPEG 인코딩은 대시보드당 한 번(최신 1개 캐시)만 하고 탭 수에 비례해 늘지 않음을 테스트로 증명하라. 아무 탭도 프레임을 요청하지 않으면 인코딩을 멈추는 기존 동작(FRAME_INTEREST_S)을 유지하라.
- Tracking 대시보드와 Sentinel Legacy drive 대시보드가 동시에 열려 있을 때 Qt 스레드 인코딩 시간 합계를 측정해 6단계 성능 표에 포함하라.

7-4. 비교 측정 절차와 기록(docs/video_relay.md 신규)
- 아래 3가지 구성을 같은 카메라·HM30·해상도·코덱으로 비교하는 절차를 문서화하라.
  ① 직접 연결 1개(Linker만) ② 직접 연결 2개(Linker + Sentinel 동시) ③ 로컬 중계 경유(Linker + Sentinel)
- 지연 측정은 Sentinel의 기존 도구 tools/measure_video_latency.py를 읽기 전용으로 사용하는 방법을 적어라(Sentinel 소스 수정 금지). Linker 쪽에는 프레임 나이·수신 FPS·끊김 횟수·재연결 횟수를 CSV로 남기는 측정 스크립트를 tools/에 추가하라.
- 기록 표: 날짜, 카메라, 해상도/코덱/비트레이트, 구성(①②③), 거리, 지연 중앙값/최소/최대, 끊김·깨짐 횟수, 재연결 횟수, 비고. 실측 전에는 "미측정"으로 두고 추정값을 넣지 말라.
- 실측 결과에 따라 중계 사용을 운용 기본값으로 할지는 사용자가 결정한다. 문서에 결정 칸을 둬라.
