- 비학습형은 사전 학습 모델뿐 아니라 온라인 분류기 학습도 사용하지 않는 것으로 해석한다. goodFeaturesToTrack + pyramidal LK 광류 + 전후방 오차/잔존점/이동 일관성 검사를 기본으로 한다. YOLO, PyTorch, 모델 다운로드, MIL은 추가하지 말라. CSRT/KCF는 온라인 적응 정책을 별도 합의하기 전까지 기본값으로 사용하지 말라.

1. Sentinel 호환성부터 확립
- 실제 발견: Linker는 health bit 0/1만 허용하며 현재 Sentinel은 CAMERA_FRESH, POSE_FRESH, GPS_3D, CLOCK_OK, COURSE_LOADED(bit 2~6)를 추가했다. tests/test_guide_stage1.py는 SentinelSession import 중 Linker의 동명 guide_protocol을 참조하여 CAMERA_FRESH ImportError가 발생한다. test_drive_dashboard.py도 의존 실패한다.
- 두 프로세스 간 wire 호환과 한 프로세스 내 Python import 호환을 분리해서 해결하라. 격리된 프로세스 fixture 또는 명시적 namespace를 사용해 sys.path 순서에 의존하지 않게 하라. 과거/현재 프로필 fixture를 각각 두어 Sentinel의 추가 필수 설정·extends·STAGE 차이를 검증하라. 상수만 복사한 뒤 완료 처리하지 말라.
- 기존 메시지 ID 52200~52206, 필드, 서명, 순번·세션·UTC·TTL·ACK·스냅샷 동기화 의미는 유지하라. 합의된 추가 health 비트만 수용하고 나머지 unknown bit는 거부하라. 구형 bit0/1 peer도 지원하라.
- 생성된 wow_guide_mavlink.py를 직접 수정하지 말라. XML 변경이 불필요하면 유지하라. Guide HEARTBEAT/ACK와 Pixhawk HEARTBEAT/COMMAND_ACK를 구분하라.
- bbox를 가짜 위경도/거리와 함께 OBSTACLE_ALERT나 DRIVE_ADVICE로 내보내지 말라. 새 추적 이벤트는 이번에는 내부 전용이다.

2. 영상과 데이터 모델
- 이미 존재하는 _SharedCapture를 재사용하라. Fly+Video4CH+Tracking에서 동일 소스 디코더는 하나여야 한다. 녹화·스냅샷·최초 구독자 transport 동작을 보존하라.
- FrameEnvelope에 source_id, session_id, frame_seq, width/height, decoder_received_monotonic을 포함하라. 원본 촬영 시각이 없으면 이를 수신 시각과 혼동하지 말라. QImage 표시 시각으로 프레임 신선도를 판단하지 말라.
- 최신 프레임 1개만 유지하는 구독 API를 설계하라. numpy 버퍼 소유권·복사·읽기 전용 정책을 명확히 하고 느린 구독자가 UI나 기존 녹화를 막지 않게 하라. Qt queued signal이 무한 누적되지 않게 하라.
- RTSP URL은 기존 정상 설정을 재사용하고 설정 가능하게 하라. 프리셋 주소를 실제 HM30 주소로 단정하지 말라. 비밀번호 포함 URL은 로그에서 가려라.
- 재접속·소스 변경·해상도 변경 시 session_id를 바꾸고 이전 추적 결과를 폐기하라. 앱 종료 시 취소·참조 해제·워커 종료를 보장하라. native read가 오래 걸려도 UI를 막거나 실행 중 QThread를 파괴하지 말라.

- 수동 ROI를 기본으로 하고 이미지 밖·너무 작은 ROI·무텍스처·NaN/Inf·잘못된 dtype/shape·역행/중복 frame seq·미래/오래된 시각을 검증하라.
- 광류 실패·가림·품질 저하·프레임 timeout·해상도 변경·재연결·작업 예외 시 LOST/ERROR로 전환하고 유효 bbox와 이전 출력을 무효화하라. LOST는 새 프레임만으로 해제하지 말고 사용자가 새 ROI를 선택해야 한다.
- 프레임 콜백과 독립된 watchdog을 두어 입력 프레임이 전혀 오지 않거나 워커가 지연될 때도 중단되게 하라. 처리중 결과가 늦게 도착해도 취소된 session_id이면 버려라.
